ТЗ: Звуковая система — двигатели, SFX, окружение, погода (дождь/гром)
В игре bajaj GO (voxel-раннер в духе Traffic Rider) необходимо добавить полноценную звуковую систему: разные звуки двигателей для каждого мотоцикла/квадрицикла, короткие эффекты (SFX), фоновое окружение, погодные звуки (дождь и гром) и отдельный блок «Настройки звука». Все аудиофайлы должны лежать в отдельной папке игры и легко заменяться владельцем в формате MP3 64 кбит/с (маленький вес). Звук должен вписываться в существующий визуальный стиль и не ломать текущие механики.

Жёсткие требования к результату
Верни один полноценный HTML-файл со встроенными HTML, CSS и JavaScript. Это должна быть полноценная работающая игра, а не заглушка или фрагмент.

Внешние библиотеки (Three.js) можно подключать через CDN.

Нельзя отдавать пустой файл, заглушку или фрагмент кода.

Не ломай текущую физику, управление, HUD, экономику (топливо, износ, доставка), сохранения, трамплины, съезды, смену времени суток, качество освещения (обычное / DLSS-стиль) и другие механики.

Звук не должен падать и не должен блокировать игру, если аудиофайлы отсутствуют: в этом случае — тишина + одно предупреждение в консоль, игра продолжается.

Все аудиофайлы — в отдельной папке sounds/, заменяемые в формате MP3 64 кбит/с.

2. Характер звука двигателей (как у реальных аналогов)
Каждый двигатель звучит по-своему, чтобы игрок слышал разницу между моделями:

К примеру: NS125 — лёгкий одноцилиндровый, высокий тон, стрекочущий, «сухой». NS200 — тот же характер, но ниже и плотнее, с лёгким рычанием. N250 — заметно ниже, ровный, с бархатистым рычанием на средних оборотах. Dominar 400 — низкий, басовитый, «утробный», с выраженной пульсацией. Dominar 1000RR — агрессивный, высокооборотистый, «визжащий», с резким подхватом. Qute — слабый квадрицикл, тарахтящий, «газонокосилка», чуть дребезжащий. Qute Юры Волкова — заряженный: низкий мотор + электрическое подвывание поверх (гибридный характер).
 
Модуляция по оборотам (обязательно): playbackRate двигателя плавно меняется от 0.55 (холостой ход, speed = 0) до 1.35 (максимальная скорость). Громкость двигателя — по реалистичной кривой: тихо на холостом, громче на средних оборотах, чуть тише на максималке; формула вида 0.12 + 0.5 * sin(π * rpmFrac), где rpmFrac = speed / maxSpeed. При нажатии газа — короткий «подхват» (кратковременное ускорение playbackRate на ~0.1 с), опционально. Для Qute Юры Волкова поверх двигателя — тихий слой электрического высокочастотного тона, привязанный к скорости. При смене байка в гараже — новый двигатель применяется со следующего заезда (не перезапускать посреди заезда). При аварии/конце заезда — плавно заглушить двигатель (ramp до 0 за 0.4 с).

3. Архитектура аудио
Добавить модуль AudioManager (внутри существующего IIFE), инициализируемый лениво по первому пользовательскому жесту (клик / тап / нажатие клавиши) — требование браузеров для AudioContext.

Основные компоненты: AudioContext создаётся по первому жесту; если state === 'suspended' — вызывается resume(). Шины громкости — каждая GainNode, подключённая к masterGain → ctx.destination: engine (мотор мотоцикла игрока), ambient (окружение: город + ветер), weather (дождь и гром), sfx (короткие эффекты), ui (клики интерфейса). Кэш буферов: fetch → arrayBuffer → decodeAudioData, сохранять в AudioManager.buffers[key] с ключами вида engine:ns125, sfx:crash, ambient:city_day, weather:rain. Плавные переходы: любое изменение громкости — через linearRampToValueAtTime (0.15–0.3 с), чтобы не было щелчков. Зацикленные источники (двигатель, дождь, город, ветер): source.loop = true, стартуют один раз, останавливаются через stop() при смене состояния. Процедурный fallback: если MP3 не загрузился (404 / ошибка декодирования) — для двигателя собрать простой синтез (2 осциллятора пилообразной формы + фильтр низких частот, частота зависит от скорости). Для остальных SFX — тишина + предупреждение в консоль.

Устойчивость: никаких падений при отсутствии файлов — все fetch/decode в try/catch, при ошибке console.warn с именем файла и продолжение без звука. Никаких утечек — каждый AudioBufferSourceNode после ended отвязывать; one-shot источники не переиспользуются. Мобильные браузеры: AudioContext создаётся после первого жеста; на iOS resume() вызывать в обработчике pointerdown/touchend. Не более N одновременных SFX одного типа (например, не больше 3 near_miss одновременно), чтобы не было каши. Загрузка аудио не блокирует старт игры: если игрок стартовал до готовности буферов — двигатель подключится по мере загрузки с плавным фейдом.

4. Привязка звуков к игровым событиям
4.1. Двигатель игрока. Запуск loop двигателя выбранного байка при startGame(). При смене байка — на следующем заезде. Каждый кадр в animate() обновлять playbackRate и громкость по speed / effStats.maxSpeed (плавная интерполяция, обновление не чаще ~30 Гц, чтобы не дёргалось).

4.2. SFX — короткие события. Авария / crashGame — sfx/crash.mp3. Отрыв с трамплина (playJumpSound('launch')) — sfx/jump_launch.mp3. Приземление (finishJumpLanding) — sfx/jump_land.mp3. Успешный перелёт над машиной — sfx/jump_overfly.mp3 (тон растёт с комбо, playbackRate = 1 + combo * 0.08). Близкий пролёт мимо машины (nearMissAwarded) — sfx/near_miss.mp3. Включение дальнего света (triggerHighBeam) — sfx/high_beam.mp3. Взят заказ в ресторане (createOrder) — sfx/order_pickup.mp3. Заказ доставлен (deliverOrder) — sfx/order_deliver.mp3. Просрочка заказа — sfx/order_fail.mp3. Заправка на АЗС — sfx/refuel.mp3. Ремонт в СТО — sfx/repair.mp3. Покупка байка / тюнинга — sfx/purchase.mp3. Клики по кнопкам меню/магазина/паузы — sfx/click.mp3.

Обёртка AudioManager.playSfx(key, { volume, rate }) создаёт BufferSourceNode (loop = false) → GainNode → шина sfx.

4.3. Окружение. При старте заезда — loop города: city_day.mp3 днём, city_night.mp3 ночью. При смене времени суток (хук в updateAtmosphereAndTimeOfDay, по флагу isNightish) — crossfade 1.5–2 с. Ветер на скорости: отдельный loop wind_high_speed.mp3, громкость = clamp((speed - 60) / 180, 0, 1) * 0.6. На малой скорости — 0.

4.4. Дождь и гром (погодное событие). Синхронизировано с событием «дождь» (см. ТЗ «Динамическая погода — дождь»). Включение дождя (weather.isRaining = true): плавно (2 с) поднять rainGain до громкости шины weather, запустить loop weather/rain_loop.mp3. Выключение дождя: плавно (2–3 с) опустить rainGain до 0, затем stop() источника. Молния → гром через задержку 1–1.5 с: в момент вспышки молнии запланировать setTimeout со случайной задержкой 1000–1500 мс, после чего проиграть случайный из thunder_01/02/03.mp3 через шину weather. Защита от наложения: если гром уже играет — новый не запускать (или максимум 1 одновременный, новый обрывает старый с коротким фейдом). Вариативность: случайный выбор файла грома и случайный playbackRate в диапазоне 0.9–1.1. Громкость грома привязать к расстоянию до молнии, если оно есть; иначе — фиксированная (~0.8 от громкости шины weather).

5. Блок «Настройки звука» в UI
Добавить раздел в меню паузы (кнопка «⚙ НАСТРОЙКИ» → вкладка «🔊 ЗВУК») и главное меню (кнопка mm-btn-sec «🔊 Настройки звука» между «Качество освещения» и «Тюнинг»). Использовать существующие CSS-классы (modal-card, pause-stats, secondary, poi-note, mm-btn-sec).

Состав настроек: ползунок «Громкость мотора мотоцикла» — шина engine, по умолчанию 70%. Ползунок «Громкость окружения (город + ветер)» — шина ambient, по умолчанию 45%. Ползунок «Громкость эффектов (SFX)» — шина sfx, по умолчанию 60%. Ползунок «Громкость погоды (дождь, гром)» — шина weather, по умолчанию 55%. Ползунок «Громкость интерфейса (клики)» — шина ui, по умолчанию 50%. Ползунок «Общая громкость» — шина master, по умолчанию 80%. Кнопка «Выкл/Вкл весь звук» — по умолчанию Вкл. Кнопка «Сброс к значениям по умолчанию». Все ползунки — диапазон 0–100%.

Требования к UI. Каждый ползунок — <input type="range" min="0" max="100"> с числовым значением справа (например, 70%). Значение сохраняется в localStorage: bajajGO_vol_engine, bajajGO_vol_ambient, bajajGO_vol_sfx, bajajGO_vol_weather, bajajGO_vol_ui, bajajGO_vol_master, bajajGO_sound_on. При изменении ползунка — мгновенно применять к соответствующей шине через linearRampToValueAtTime (0.1 с). Стилизовать ползунки в текущей тёмно-синей voxel-эстетике: трек — тонкая полоса rgba(255,255,255,.15), заполнение — акцентный цвет (#00b0ff для engine, #69f0ae для ambient, #ffd54f для sfx, #4fc3f7 для weather, #e0e0e0 для master), бегунок — квадрат со скруглением. Кроссбраузерно (::-webkit-slider-thumb, ::-moz-range-thumb). Кнопка «Выкл весь звук» при включении обнуляет masterGain (не сами ползунки), состояние переживает перезагрузку. При инициализации AudioManager и каждом изменении ползунка — синхронизировать GainNode с сохранёнными значениями. При sound_on === false — masterGain = 0.

6. Пауза и состояния игры
На паузе весь звук приостанавливается: AudioContext.suspend() (надёжнее для loop) либо ramp master до 0 за 0.2 с. При resumeGame — AudioContext.resume() / ramp обратно. Дождь не идёт в меню, паузе, гараже, магазине, СТО, АЗС, ресторане и других модалках — только в активном заезде. Таймеры дождя на паузе не тикают. При перезапуске заезда звуковые таймеры сбрасываются, двигатель запускается заново. При краше двигатель/окружение/дождь плавно замолкают, играет sfx/crash.mp3.

7. Точки интеграции в существующем коде
Минимально вторгаться в текущую логику. В начале IIFE объявить AudioManager; первый pointerdown/keydown на document (once) → AudioManager.init(). В startGame() запустить engine loop и ambient (город + ветер); учесть текущий байк и время суток. В crashGame() остановить engine/ambient/weather, проиграть crash. В finishJumpLanding() — приземление; при hardPitch — лёгкий скрежет (опционально). В triggerHighBeam() — high_beam. В deliverOrder(), createOrder(), при просрочке — соответствующие SFX. На кнопках fuel-fill, [data-service] — refuel, repair. На всех data-buy*, data-toggle-upg — purchase. В updateAtmosphereAndTimeOfDay при смене isNightish делать crossfade ambient-города. В игровом цикле animate() обновлять playbackRate и громкость двигателя по скорости, ветра — по скорости. В togglePause / resumeGame — приостановка / возобновление звука. В renderPauseMenu — кнопка «🔊 ЗВУК» рядом с существующей «⚙ НАСТРОЙКИ» (или внутри неё — вкладка). В renderMainMenu — кнопка mm-btn-sec «🔊 Настройки звука» между «Качество освещения» и «Тюнинг». В saveGarage() добавить сохранение bajajGO_vol_* и bajajGO_sound_on (или отдельная saveAudioSettings() — вызывать при изменении ползунков). В showEcoToast (опционально) — ui/click при клике на кнопки закрытия модалок.

8. Производительность
Аудио не должно создавать лишнюю нагрузку: все буферы грузятся один раз и кэшируются. Зацикленные источники (двигатель, дождь, город, ветер) не пересоздаются каждый кадр, живут до смены состояния. Обновление playbackRate и громкости двигателя — не чаще ~30 Гц, с плавной интерполяцией. Никаких лишних setTimeout/setInterval в игровом цикле для звука (кроме отложенного грома). Работает на обычных ПК стабильно, без просадок FPS. Звук работает с камерой кокпита и видом от третьего лица, не перекрывает HUD.

9. Что НЕ нужно менять
Не менять игровую логику, физику, экономику, внешний вид сцены — только добавить звук и UI-блок настроек звука. Не переписывать playJumpSound, spawnFloatingPopup, spawnOverflyParticles — только заменить/дополнить их вызовы новыми звуками из AudioManager. Не ломать существующие сохранения localStorage — новые ключи добавлять, старые не трогать.

10. Чек-лист перед выдачей
Игра запускается без ошибок, все прежние системы работают. Папка sounds/ со структурой из п.1 и README.txt. AudioManager с шинами и сохранением настроек. Двигатель звучит по-разному для всех 7 байков, меняет тон и громкость от скорости. Городской фон днём/ночью с crossfade, ветер на скорости. Все SFX из таблицы п.4.2 подключены. Дождь (loop) и гром через 1–1.5 с после молнии — готово к интеграции с погодным событием (функции setWeather('rain'), triggerLightning() в AudioManager). Блок «Настройки звука»: 6 ползунков + toggle + сброс, сохранение в localStorage, мгновенное применение. Пауза глушит/приостанавливает звук, resumeGame — возвращает. Отсутствие файлов не ломает игру (тишина + предупреждение). Все файлы MP3 64 кбит/с, README.txt объясняет, как заменить. Дождь не звучит в меню/паузе, корректно работает с обеими камерами. Стабильный FPS, пуллинг и переиспользование буферов.

Главный принцип: звук — это атмосфера и характер техники, которая делает заезды живыми и узнаваемыми, но не мешает игроку: разные двигатели, ненавязчивое окружение, короткие SFX, тихий дождь с редким громом, полный контроль громкости по шинам — без потери читаемости и производительности.
