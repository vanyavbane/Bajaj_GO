# Промпт для GLM-5/3 Flash Free — новые параметры настроек (HDR+, резкость, яркость)

## Контекст

Игра «bajaj GO» на Three.js, код в `bajaj-go.html` (минифицирован). Есть экран настроек с категориями (в т.ч. «Освещение» и «Графика»). Нужно добавить три новых параметра в настройки и реализовать постобработку изображения. Код минифицирован — ищи по смыслу (строки типа `settings`, `lighting`, `graphics`, `render`, `composer`, `postprocessing`, `toneMapping`, `Exposure`, `ShaderPass`, `EffectComposer`, `localStorage`, `slider`, `range`, `input type="range"`).

---

## Общие требования

1. **Не ломать существующие настройки** — новые параметры добавляются рядом с существующими, с теми же стилями UI (слайдеры/переключатели), с сохранением в `localStorage` вместе с остальными настройками.
2. **Постобработка** — если в проекте уже есть `EffectComposer` (Three.js postprocessing), использовать его; если нет — добавить цепочку `EffectComposer` + `ShaderPass` (или `RenderPass` + проходы). Не ломать существующий рендер.
3. **Мобильная производительность** — шейдеры лёгкие, без тяжёлых вычислений; на слабых устройствах параметры не должны «ронять» FPS. Если нужно — использовать `resolution` из `renderer.getPixelRatio()` и не гонять fullscreen-проходы дважды.
4. **Значения по умолчанию — как сейчас**, то есть:
   - HDR+ — **выключен** (эффект не накладывается, картинка как сейчас).
   - Резкость — **0** (изображение как сейчас, без изменения).
   - Яркость — **0** (изображение как сейчас, без изменения).
   При `0`/`off` постобработка должна давать **пиксель-в-пиксель** исходное изображение (или максимально близко; допускается незначительная разница из-за прохода, но без видимых изменений).

---

## Параметр 1. Освещение → HDR+

**Что нужно:**
- В категорию настроек **«Освещение»** добавить переключатель **«HDR+»** (вкл/выкл; по умолчанию **выкл**).
- При включении на изображение накладывается эффект **HDR+**: локальное тональное сжатие (local tone mapping) с подчёркиванием деталей в тенях и светах, без «плоского» вида и без яростных пересветов. Визуально — как HDR-фото: более выразительные света/тени, повышенная локальная контрастность, но естественно.
- Реализация: полноэкранный шейдер-проход (например, `HDRPlusPass`), который:
  - берёт текущий кадр;
  - выполняет локальное тональное отображение (можно упрощённый вариант: гауссово размытие яркости в 2–3 прохода с уменьшенным разрешением → локальная адаптация → смешивание с исходником);
  - не допускает клиппинга (пересветов) — использовать мягкое сжатие (`smoothstep`/`1 - exp(-x)`-подобное);
  - при выключении — проход отключается (или возвращает исходник без изменений).
- Не конфликтовать с существующим `toneMapping`/`Exposure` — HDR+ применяется **после** основного рендера, но **до** UI. Если в проекте уже есть `toneMapping`, HDR+ не должен его «перетирать» — либо работать поверх, либо аккуратно комбинировать.
- Сохранять состояние в `localStorage` (ключ в стиле существующих настроек).

**Критерий приёмки:** при выкл. — картинка как сейчас; при вкл. — видимый HDR-эффект (детали в тенях/светах), без пересветов и без падения FPS ниже разумного на мобильном.

---

## Параметр 2. Графика → Резкость

**Что нужно:**
- В категорию **«Графика»** добавить слайдер **«Резкость»** (диапазон, например, `-100…+100` или `-1…+1`, с шагом; по умолчанию **0** = как сейчас).
- При значении **< 0** изображение становится **мягче** (blur/soften), при **> 0** — **резче/чётче** (sharpen).
- Реализация: полноэкранный шейдер-проход (`SharpenPass`), который:
  - при `0` — возвращает исходник без изменений (пиксель-в-пиксель, без лишнего блюра);
  - при `> 0` — unsharp mask / свёртка (например, 3×3 или 5×5 kernel) с силой, пропорциональной значению;
  - при `< 0` — мягкое размытие (например, гауссово 3×3 или смешивание с размытой версией) с силой, пропорциональной модулю значения;
  - использовать `texture2D` с `texelSize` от `resolution` (не хардкодить пиксели);
  - не допускать «звона» (overshoot) на резких краях при больших значениях — ограничить clamp.
- Слайдер: подпись «Резкость», отображение текущего значения, кнопка/двойной тап «сбросить в 0» (если в UI проекта есть такой паттерн — использовать его).
- Сохранять в `localStorage`.

**Критерий приёмки:** при `0` — картинка как сейчас; при `> 0` — заметно чётче; при `< 0` — заметно мягче; без артефактов «звона» и без падения FPS.

---

## Параметр 3. Графика → Яркость

**Что нужно:**
- В категорию **«Графика»** добавить слайдер **«Яркость»** (диапазон, например, `-100…+100` или `-1…+1`; по умолчанию **0** = как сейчас).
- При регулировке изменяется **яркость изображения**, но **без яростных пересветов**: нельзя просто умножать RGB на коэффициент (это клиппит света). Нужно использовать мягкое тональное изменение:
  - например, в линейном пространстве: `color = color * pow(2, brightness)` с последующим мягким сжатием (`color / (1 + color)` или `1 - exp(-color)`) для защиты от пересветов;
  - либо работать в `sRGB` с `smoothstep`-сжатием верхнего диапазона;
  - либо использовать `renderer.toneMappingExposure` (если проект на нём) — но тогда следить, чтобы не конфликтовать с HDR+ и существующим exposure; если конфликт — сделать отдельный проход.
- Реализация: полноэкранный шейдер-проход (`BrightnessPass`) **или** настройка `toneMappingExposure` (предпочтительно, если проект уже использует tone mapping — меньше проходов). При `0` — без изменений.
- Слайдер: подпись «Яркость», текущее значение, сброс в 0.
- Сохранять в `localStorage`.

**Критерий приёмки:** при `0` — картинка как сейчас; при `+` — ярче, но света не «выжигаются» в белое; при `-` — темнее, без «чёрных провалов» в тенях; без падения FPS.

---

## Порядок проходов постобработки

Если все три параметра активны, порядок должен быть таким (чтобы не ломать друг друга):
1. Основной рендер сцены (`RenderPass`).
2. **Яркость** (если `≠ 0`) — мягкое изменение экспозиции.
3. **HDR+** (если вкл.) — локальное тональное сжатие.
4. **Резкость** (если `≠ 0`) — sharpen/soften **последним**, чтобы не размывать HDR-эффект.
5. UI поверх (если UI рендерится отдельно — не трогать).

Если какой-то параметр в дефолте (`0`/`off`) — соответствующий проход **не добавляется в цепочку** (или шорткатится), чтобы не тратить FPS.

## UI и сохранение

- Новые элементы — в тех же стилях, что существующие настройки (шрифт, отступы, цвет, поведение слайдеров на тач).
- Подписи: «HDR+» (Освещение), «Резкость» (Графика), «Яркость» (Графика).
- Значения по умолчанию: HDR+ — вкл., Резкость — 0, Яркость — 0.
- Сохранение/загрузка в `localStorage` вместе с остальными настройками (тот же ключ/объект, что и сейчас; если настройки хранятся одним JSON — добавить поля `hdrPlus: false`, `sharpness: 0`, `brightness: 0`).
- При сбросе настроек «по умолчанию» — новые параметры тоже сбрасываются в дефолт.

## Формат ответа

Для каждого параметра:
1. Где найдено место (функция/фрагмент, якоря до/после).
2. Патч (diff или «было → стало»).
3. Как реализован шейдер/проход (кратко), какие uniform'ы.
4. Что добавлено в UI и в `localStorage`.
5. Критерий проверки (вкл/выкл, `0`, `+`, `-`).

Если точное место не найдено — укажи, по каким строкам/символам искать (`EffectComposer`, `ShaderPass`, `settings`, `localStorage`, `toneMappingExposure` и т.п.), и предложи вероятный патч с оговоркой. Если в проекте **нет** `EffectComposer` — предложи минимальную цепочку из `RenderPass` + `ShaderPass` (Three.js `examples/jsm/postprocessing`), но с оговоркой, что нужно подключить модули (если они уже в бандле — использовать; если нет — сообщить, что потребуется добавить импорт).
