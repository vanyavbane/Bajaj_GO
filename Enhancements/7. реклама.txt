ТЗ: Папка AdManager — загрузка рекламных материалов из файлов проекта 
В игре bajaj GO (voxel-раннер в духе Traffic Rider) необходимо добавить возможность показывать на существующих рекламных стендах вдоль трассы собственные рекламные материалы, которые владелец игры кладёт в отдельную папку AdManager/ рядом с bajaj go.html. Никакой кнопки в меню и никакого UI загрузки файлов через браузер не нужно — владелец просто кладёт файлы в папку, и они автоматически подхватываются игрой и добавляются к уже существующим процедурным рекламам как разнообразие (а не заменяют их). Архитектура должна быть готова к будущему подключению рекламы Google Play без переписывания игровой логики.

Жёсткие требования к результату
Верни один полноценный HTML-файл со встроенными HTML, CSS и JavaScript. Это должна быть полноценная работающая игра, а не заглушка или фрагмент.

Внешние библиотеки (Three.js) можно подключать через CDN.

Не ломай текущую физику, управление, HUD, экономику (топливо, износ, доставка), сохранения, трамплины, съезды, смену времени суток, качество освещения (обычное / DLSS-стиль) и другие механики.

Существующие рекламные стенды (билборды slot.billboard, оверхеды slot.portal, боковые панели) продолжают работать с процедурными текстурами из billboardTextures и overheadSignTextures. Материалы из AdManager/ встраиваются в общий пул и показываются на тех же стендах как дополнительные варианты (случайный выбор), а не заменяют существующие.

Никаких кнопок в главном меню, меню паузы или где-либо ещё. Никакого <input type="file">. Никакой загрузки через браузер. Владелец кладёт файлы в папку проекта — игра их находит сама.

Форматы: изображения — JPG/PNG/WebP; видео — MP4/WebM, без звука (звук у видео принудительно отключается/игнорируется). Для видео — лимит длительности (например, до 10 секунд) и размера (например, до 10 МБ), с молчаливым пропуском файла при превышении и предупреждением в консоль.

Если папки AdManager/ нет, она пуста или в ней нет валидных файлов — игра работает как раньше, только с процедурной рекламой. Никаких ошибок, никаких падений, никакого визуального мусора.

Архитектура готова к будущему подключению Google Play через единый AdManager-интерфейс, без правок в игровой логике.

1. Папка AdManager/ и её структура
Рядом с bajaj go.html создать папку AdManager/ следующей структуры:

text
AdManager/
├── billboards/          — материалы для обычных билбордов (16:9, рекомендуется 1280×720)
│   ├── *.jpg
│   ├── *.png
│   ├── *.webp
│   ├── *.mp4            — без звука, до 10 секунд
│   └── *.webm           — без звука, до 10 секунд
├── overheads/           — материалы для оверхеды-указателей над дорогой (16:9, рекомендуется 1280×720)
│   ├── *.jpg / *.png / *.webp
│   └── *.mp4 / *.webm   — без звука; на оверхедах показывается только постер (первый кадр), видео не воспроизводится
├── README.txt           — инструкция для владельца: что класть, в каком формате, какие лимиты, как называть файлы
└── manifest.json        — ОПЦИОНАЛЬНЫЙ файл (см. п.2); если его нет — игра формирует список файлов автоматически (если браузер/сервер позволяют) или использует fallback-механизм (см. п.3)
Имена файлов — произвольные, латиница/цифры/дефисы/подчёркивания, без пробелов (пробелы заменять на _). Расширение определяет тип. Никаких требований к порядку — игра сама выбирает случайный файл при показе на стенде.

Рекомендации по содержимому (записать в README.txt):

Изображения — JPG/PNG/WebP, соотношение сторон как у соответствующего стенда, вес до 5 МБ.

Видео — MP4 (H.264) или WebM (VP9), без звуковой дорожки, длительность до 10 секунд, вес до 10 МБ, разрешение не выше (16:9, рекомендуется 1280×720 или ниже) (для билбордов) — чтобы не грузить GPU.

Все материалы — в стилистике игры (voxel, не фотореализм, без ярких кислотных цветов и пересветов), чтобы не выбиваться из визуала.

2. Механизм обнаружения файлов (без серверного бэкенда)
Поскольку игра — статический HTML-файл, браузер сам по себе не умеет читать содержимое папки. Нужно предусмотреть три уровня обнаружения, чтобы работало в разных условиях:

Уровень 1 — AdManager/manifest.json (рекомендуемый и основной). Владелец создаёт manifest.json со списком файлов. Формат:

text
{
  "version": 1,
  "billboards": ["promo1.jpg", "promo2.mp4", "sale.webp"],
  "overheads": ["exit_sign_1.png", "exit_sign_2.jpg"]
}
Если файл есть и валиден — игра использует только перечисленные файлы. Это самый надёжный способ, работает всегда, включая file://.

Уровень 2 — автолистинг через fetch (если сервер отдаёт directory listing). Если manifest.json нет, игра пробует fetch('AdManager/billboards/') и fetch('AdManager/overheads/'), парсит HTML-ответ, извлекает ссылки на файлы с поддерживаемыми расширениями. Работает только на серверах с включённым directory listing (например, python -m http.server, npx serve, некоторые CDN). На file:// и на серверах без листинга — не работает, переходим на уровень 3.

Уровень 3 — fallback-заглушка без рекламы из папки. Если ни manifest.json, ни автолистинг не сработали — игра работает только с процедурной рекламой, как сейчас. В консоль — одно предупреждение: «AdManager: не удалось обнаружить файлы рекламы. Создайте AdManager/manifest.json со списком файлов (см. AdManager/README.txt). Игра продолжит работу с процедурной рекламой.» Никаких ошибок, никаких видимых изменений для игрока.

Кэширование обнаружения: результат обнаружения сохранять в sessionStorage (ключ bajajGO_adManagerDiscovery) на время сессии, чтобы не дёргать fetch при каждом старте заезда. При перезагрузке страницы — заново. Владелец, добавивший новые файлы, может очистить кэш через Ctrl+F5 (жёсткая перезагрузка) или удалить ключ вручную — это указать в README.txt.

3. Загрузка и подготовка материалов
Для каждого обнаруженного файла:

Изображения — new Image() с src = 'AdManager/billboards/<file>' (или overheads/<file>), crossOrigin = 'anonymous', await img.decode(). После загрузки — создать THREE.Texture (если ещё не создана) с colorSpace = THREE.SRGBColorSpace, needsUpdate = true. Хранить в AdManager.images.billboards[] и AdManager.images.overheads[] как { file, texture, image }. Не создавать objectURL — браузер сам закэширует по URL.

Видео — document.createElement('video'), src, muted = true, playsInline = true, loop = true, preload = 'auto', crossOrigin = 'anonymous'. Дождаться loadedmetadata — проверить duration <= 10 и videoWidth/videoHeight (не больше 1024×384 — иначе пропустить с предупреждением). Сгенерировать постер (первый кадр) через canvas.toDataURL('image/jpeg', 0.85) — сохранить как THREE.Texture для показа на дальних стендах и оверхедах. Создать THREE.VideoTexture только при необходимости (лениво, при первом показе на ближайшем стенде). Хранить в AdManager.videos.billboards[] как { file, videoEl, videoTexture, posterTexture, duration, width, height, lastActive }.

Ошибки загрузки — try/catch вокруг каждого файла; при ошибке — console.warn('AdManager: не удалось загрузить <file>', err) и пропустить файл. Остальные файлы грузятся нормально. Игра не падает.

Загрузка не блокирует игру: все файлы грузятся асинхронно после старта игры (или параллельно с главным меню). Пока материал не загружен — используется процедурная текстура. По мере готовности — новые материалы становятся доступны для выбора на стендах.

4. Модуль AdManager — единая точка выбора баннера
Создать внутри IIFE модуль AdManager со следующим публичным API (внутренним, но стабильным контрактом):

text
AdManager.init()                                  // запускает обнаружение и загрузку файлов из папки AdManager/
AdManager.pickBannerForSlot(slot)                 // возвращает { texture, isVideo, videoTexture? } для конкретного стенда
AdManager.getStats()                              // { billboardsLoaded, overheadsLoaded, billboardsTotal, overheadsTotal }
AdManager.registerExternalProvider(provider)      // заглушка для будущего Google Play
AdManager.reportImpression(bannerId)              // заглушка для будущего Google Play
AdManager.registerSettingsListeners()              // (опционально) для будущей интеграции с настройками
Логика pickBannerForSlot(slot):

Определить тип стенда: slot.kind === 'billboard' (обычный билборд — можно изображение или видео) или slot.kind === 'overhead' (оверхед — только изображение/постер, видео не воспроизводится).

С вероятностью P_uploaded (по умолчанию 50%, константа AD_UPLOADED_SHARE = 0.5) — если в AdManager есть загруженные материалы соответствующего типа, выбрать случайный. Для билбордов — если выбран видео-материал, вернуть { texture: videoTexture, isVideo: true, videoEl }; если изображение — { texture: imageTexture, isVideo: false }. Для оверхеды — всегда { texture: posterTexture, isVideo: false } (даже если это видео — берём постер).

Иначе — вернуть null, и вызывающий код использует процедурную текстуру, как сейчас.

Если загруженных материалов нет — всегда null (только процедурная реклама).

Ограничение на видео: одновременно активных VideoTexture — не более 2. В pickBannerForSlot для видео проверять, сколько videoTexture сейчас «в игре» (по lastActive и расстоянию до игрока); если лимит исчерпан — вернуть постер ({ texture: posterTexture, isVideo: false }). Это гарантирует FPS.

Отчёты о показах: при фактическом присвоении текстуры стенду — вызывать AdManager.reportImpression(banner.file) (сейчас — no-op, в будущем — отправка в провайдер).

5. Показ на существующих стендах
Не менять геометрию, размеры и расположение билбордов и оверхедов. Изменить только источник текстуры.

В createBillboardMesh(texIndex, withSpotlights) и в создании оверхеды (slot.portal) — вместо прямого присвоения billboardTextures[texIndex % billboardTextures.length] вызывать AdManager.pickBannerForSlot({ kind: 'billboard' | 'overhead' }). Если вернулся объект — использовать его текстуру; иначе — процедурную, как сейчас.

При смене текстуры стенда (когда слот ушёл за спину игрока и при следующем показе выбирается заново — например, в updateRoadSurface / при обновлении slot.billboard.faceMat.map) — каждый раз вызывать AdManager.pickBannerForSlot заново. Это даёт естественное разнообразие: разные стенды показывают разные материалы, включая загруженные из папки.

Видео на ближайших стендах: в animate() раз в ~0.5 секунды проверять, какие стенды с видео находятся впереди игрока на расстоянии до ~120 метров; для них — video.play() (если ещё не играет) и videoTexture.needsUpdate = true; для остальных — video.pause(). Это гарантирует, что видео декодируется только когда реально видно, и не тратит ресурсы.

Видео без звука: у каждого video элемента — muted = true, volume = 0, playsInline = true, loop = true. Атрибут muted выставлять в HTML и JS, чтобы никакие браузерные политики не блокировали автовоспроизведение.

Видео на оверхедах — только постер. Оверхед — это дорожный указатель, там видео не нужно и дорого. В pickBannerForSlot для kind === 'overhead' всегда возвращать только posterTexture.

6. Настройки показа (без UI — константы в коде + localStorage)
UI для разработчика не добавляем (по требованию «без кнопки в меню»). Но чтобы владелец мог гибко настраивать поведение, предусмотреть константы в начале кода с комментариями:

text
const AD_UPLOADED_SHARE = 0.5;          // 0..1 — доля загруженных материалов в показе (остальное — процедурные)
const AD_MAX_ACTIVE_VIDEOS = 2;         // максимум одновременно воспроизводимых видео
const AD_VIDEO_MAX_DURATION_SEC = 10;   // лимит длительности видео
const AD_VIDEO_MAX_SIZE_MB = 10;        // лимит размера видео
const AD_VIDEO_MAX_RESOLUTION = 1024;   // макс. ширина видео по горизонтали
const AD_VIDEO_ACTIVE_DISTANCE_M = 120; // дистанция, на которой видео воспроизводится
const AD_AUTODETECT_ENABLED = true;     // включить автообнаружение файлов (manifest + fetch)
Владелец может менять эти значения прямо в коде, если захочет. Дополнительно — при наличии localStorage-ключей bajajGO_adUploadedShare (число 0..1) и bajajGO_adEnabled ('0'/'1') — они переопределяют константы (на случай, если в будущем появится UI или консольный хак). Сейчас эти ключи никто не пишет — они просто читаются, если есть.

7. Готовность к Google Play (заглушка без реальных вызовов)
Внутри AdManager создать публичный API (внутренний контракт):

text
AdManager.registerExternalProvider(provider)
AdManager.unregisterExternalProvider(providerId)
AdManager.reportImpression(bannerId)
AdManager.reportClick(bannerId)
Контракт provider:

text
{
  id: string,
  getName(): string,
  getBanners(): Promise<Array<{ id, type: 'image'|'video', srcUrl, posterUrl, duration, enabled }>>,
  onShown(bannerId): void,
  onClicked(bannerId): void
}
pickBannerForSlot должен учитывать внешних провайдеров наравне с загруженными из папки: сначала проверяется наличие внешних баннеров, затем — загруженных из папки, затем — процедурных. Сейчас registerExternalProvider никем не вызывается, поэтому внешних баннеров нет — логика работает только с папкой и процедурной рекламой. Но точка интеграции готова: в будущем подключение Google Play сведётся к одному вызову AdManager.registerExternalProvider(googlePlayProvider) — без изменений в createBillboardMesh, animate() и других местах.

8. Производительность и устойчивость
Никаких падений, если папки AdManager/ нет, она пуста, manifest.json отсутствует или содержит битые пути. Все fetch/decode/img.decode() — в try/catch, ошибки — в console.warn, игра продолжается.

Никакой загрузки текстур каждый кадр — только при смене выбранного баннера на стенде (событие, а не кадр).

VideoTexture — не более AD_MAX_ACTIVE_VIDEOS одновременно. Остальные видео — пауза + постер.

Изображения кэшируются браузером по URL — не создавать objectURL каждый раз.

THREE.Texture для одного и того же файла — создавать один раз, хранить в AdManager.images / AdManager.videos, переиспользовать.

Стабильный FPS на обычных ПК даже при наличии видео-материалов в папке.

Работает с камерой кокпита и видом от третьего лица, не перекрывает HUD.

При file:// (открытие HTML-файла напрямую) — fetch к manifest.json может блокироваться CORS. В этом случае — сработает fallback (уровень 3, только процедурная реклама) и предупреждение в консоль. В README.txt указать: «Для работы загруженной рекламы запускайте игру через локальный сервер (например, python -m http.server) или разместите файлы на хостинге; открытие через file:// может ограничивать загрузку рекламы из папки».

9. Что НЕ нужно менять
Не добавлять кнопок в главное меню, меню паузы, магазин, тюнинг и любые другие экраны.

Не добавлять <input type="file">, drag-and-drop, UI загрузки файлов в браузере.

Не менять игровую логику, физику, экономику, внешний вид сцены — только источник текстуры для стендов и модуль AdManager.

Не переписывать billboardTextures, overheadSignTextures, createBillboardMesh, createOverpassStructure — только дополнить их вызовом AdManager.pickBannerForSlot.

Не ломать существующие сохранения localStorage — новые ключи (bajajGO_adUploadedShare, bajajGO_adEnabled, bajajGO_adManagerDiscovery) добавлять, старые не трогать.

10. Чек-лист перед выдачей
Игра запускается без ошибок, все прежние системы работают. Папка AdManager/ со структурой из п.1 и README.txt присутствует в проекте. Кнопок в меню для рекламы нет. AdManager.init() вызывается при старте игры, обнаруживает файлы через manifest.json, затем через автолистинг, затем — fallback на процедурную рекламу. Загруженные из папки изображения и видео показываются на существующих билбордах как дополнительные варианты (вероятность AD_UPLOADED_SHARE), не заменяя процедурные. Видео воспроизводятся только на ближайших билбордах (не более AD_MAX_ACTIVE_VIDEOS одновременно), без звука, остальные стенды показывают постер. На оверхедах — только изображения/постеры, без видео. При отсутствии папки / файлов / manifest.json игра работает только с процедурной рекламой и пишет одно предупреждение в консоль. AdManager — единая точка выбора баннера для слота, готовая к подключению Google Play через registerExternalProvider без правок в игровой логике. Стабильный FPS, пуллинг и переиспользование текстур. Работает с камерой кокпита и видом от третьего лица, не перекрывает HUD.

Главный принцип: владелец игры просто кладёт свои рекламные материалы в папку AdManager/ проекта и составляет manifest.json — игра автоматически подхватывает их и показывает на существующих стендах как разнообразие к процедурной рекламе. Никакого UI загрузки, никаких кнопок в меню, никаких браузерных диалогов. Архитектура AdManager готова к будущему подключению Google Play одним вызовом, без переписывания игровой логики.
