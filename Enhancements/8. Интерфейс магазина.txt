# Промпт: переработка экрана «Магазин мотоциклов» (bajaj GO)

Отдельное ТЗ на переработку экрана магазина. Стиль — общий BF3 из основного промпта (тонкие рамки, 2px радиус, прозрачность 0.62–0.82, uppercase, `--bf-accent` / `--bf-signal`). Фон с мотоциклом за меню не трогаем — он остаётся виден за полупрозрачной подложкой.

---

## 🎯 ЗАДАЧА

Переработать экран магазина из вертикального списка карточек в **двухколоночный layout**:

- **Левая колонка (левее центра):** список мотоциклов (компактные строки-кнопки, а не крупные карточки).
- **Правая колонка (правее центра):** вращающаяся 3D-модель выбранного мотоцикла без мотоциклиста, под ней — характеристики, пробег (если куплен) и кнопка покупки/выбора.

Сейчас всё свалено в один вертикальный список карточек — это надо заменить.

## 📋 ЛЕВАЯ КОЛОНКА — СПИСОК МОТОЦИКЛОВ

**Компактная строка-кнопка** (замена `.ds-card` в магазине):

```
Фон:            rgba(15,22,30,0.7)
Рамка:          1px solid var(--bf-line)
Радиус:         2px
Паддинг:        10px 14px
Дисплей:        flex; align-items: center; justify-content: space-between; gap: 10px
Курсор:         pointer
Hover:          фон #121a24, рамка var(--bf-line-strong)
Активная (выбранный для просмотра): рамка var(--bf-accent), левая полоса 3px var(--bf-accent), фон var(--bf-accent-dim)
Выбранный для игры: метка «✓ ВЫБРАН» цветом var(--bf-ok)
```

Внутри строки:
- Слева: название мотоцикла (13px, 700, uppercase) + под ним тип (`Мотоцикл` / `Квадрицикл`) 10px `--bf-text-dim`.
- Справа: цена (`--bf-signal`, моноширинный) или метка «В ГАРАЖЕ» (`--bf-ok`), или «НЕ ХВАТАЕТ X ₽» (`--bf-danger`).
- Клик по строке — **выбирает мотоцикл для просмотра** в правой колонке (не покупает, не выбирает для игры — только показывает).

Список сортировать по `maxSpeed`, затем по цене (как сейчас). Выбранный для просмотра — подсвечен рамкой `--bf-accent`; выбранный для игры — дополнительно метка «✓ ВЫБРАН» (`--bf-ok`) и вертикальная полоса слева.

## 🏍️ ПРАВАЯ КОЛОНКА — МОДЕЛЬ, ХАРАКТЕРИСТИКИ, КНОПКА

### 1. Вращающаяся 3D-модель

- Отдельный `WebGLRenderer` (или отдельная сцена + камера на том же рендерере — по возможности использовать существующий `i.renderer` с offscreen-рендером в canvas в правой колонке). Модель **не должна** двигаться по дороге — статичная сцена: пол-подиум (тонкий диск, тёмный), 3–4 источника света (key + fill + rim + hemi), нейтральный фон.
- Модель собирать из уже существующих `i.bikeVersionGroups[id]` (клонировать/переиспользовать геометрию), либо через существующую логику `bikeChassisGroup`/`bikeThirdPersonBody` — но в изолированной сцене магазина.
- **Вращение:** медленное, `0.35 рад/сек` вокруг вертикальной оси (Y). Скорость не зависит от FPS (`rotate.y += delta * 0.35`). Пауза вращения при `document.hidden`.
- Область рендера: `aspect-ratio: 4 / 3`, `min-height: 260px`, `max-height: 42vh`, рамка `--bf-line`, фон `#080c12`, скругление 2px. Сверху слева метка «ПРОСМОТР» на полупрозрачной подложке `rgba(0,0,0,.7)` — стиль `.cam-preview-tag`.
- Под моделью — тонкая полоса-подиум `--bf-accent` (1px), чтобы модель «стояла».
- При смене выбранного мотоцикла — модель **плавно подменяется** (fade 150ms или мгновенно, но без перезагрузки сцены). Вращение сбрасывается в 0 при смене.
- Переиспользовать материалы `i.M` и цвет кузова `fd(bike, i.customColors)` — модель должна быть в том же цвете, что в гараже.

### 2. Характеристики (под моделью)

Сетка `.ds-stats` в стиле BF3 — 2 колонки, подписи 10px uppercase `--bf-text-dim`, значения 14px моноширинным:

- **Макс. скорость:** `{baseMaxSpeed} км/ч` (если есть тюнинг — `{baseMaxSpeed} → {maxSpeed} км/ч`, прирост `--bf-ok`).
- **Разгон:** `{accel}` (с бонусом тюнинга — `{accel} (+{accelBonusPct}%)`).
- **Тюнинг:** `{installedCount}/{tuningCatalog.length}`.
- **Тип:** `Мотоцикл` / `Квадрицикл` (или `Квадрицикл (заряженный)` для `qute_yura`).
- **Пробег** (только если куплен) — см. п. 3.

### 3. Пробег (только для купленных)

Если мотоцикл есть в `i.ownedBikes`:

- Строка в характеристиках: `ПРОБЕГ` → значение `{distanceOnBike} м` (или км, если ≥ 1000 м — через `$o()`), моноширинным, цвет `--bf-signal`.
- Если пробег ещё 0 — «ещё не ездили» (`--bf-text-mute`, 11px).
- Источник данных: нужно **завести учёт пробега по каждому мотоциклу**. Варианты:
  - хранить в `localStorage` под ключом `bajajGO_mileage` — объект `{ [bikeId]: meters }`;
  - накапливать в `i.distance` каждого заезда и записывать при завершении заезда / выходе в меню / `pagehide` (по аналогии с `persistBiome`).
  - при смене выбранного мотоцикла — показывать его собственный пробег.
- Форматирование: `< 1000 м` — `123 м`; `≥ 1000 м` — `1.23 км` (через существующий `$o()`).

### 4. Кнопка действия (под характеристиками)

Одна **широкая primary-кнопка**, состояние зависит от статуса мотоцикла:

- **Уже выбран для игры:** `✓ ВЫБРАН` — primary с рамкой `--bf-ok`, disabled (неактивна, но видна).
- **Куплен, но не выбран:** `ВЫБРАТЬ` — primary `--bf-accent`, активна → по клику `selectedBikeId = id`, сохранение, обновление магазина.
- **Не куплен, хватает денег:** `КУПИТЬ ЗА {price} ₽` — primary `--bf-signal` (жёлтая рамка/текст, заливка `rgba(240,180,41,0.15)`), по клику покупка (как сейчас: списание `bankPoints`, добавление в `ownedBikes`, автовыбор).
- **Не куплен, не хватает:** `НУЖНО {price} ₽` + под кнопкой 11px `--bf-danger` «Не хватает {missing} ₽» — disabled.
- **Бесплатный стартовый (`boxer100es`):** `ВЫБРАТЬ` или `✓ ВЫБРАН`, без цены.

Кнопка — `width: 100%`, `height: 48px`, стиль primary из основного промпта (скошенный угол `clip-path`, uppercase, letter-spacing .08em). Под кнопкой — строка статуса 11px `--bf-text-dim`: например «В гараже с 12.03.2025» (если хранить дату покупки — опционально) или «Тюнинг: 2/8 · Пробег: 1 234 м» (дублирование ключевых данных, если нужно).

### 5. Свотчи цветов (если есть у мотоцикла)

Под кнопкой — ряд квадратов 24×24, рамка 1px `--bf-line-strong`, активный — 2px `#fff`, при клике — `customColors[id] = hex`, перерисовка модели в новой сцене. Подпись «Окраска» слева 10px uppercase `--bf-text-dim`.

## 📱 МОБИЛЬНАЯ ВЕРСИЯ (вертикальный телефон, `max-width: 680px`)

Двухколоночный layout на телефоне **не влезает** — перестроить в одну колонку сверху вниз:

1. **Шапка:** логотип-компакт + баланс в одну строку `display: flex; justify-content: space-between;` (баланс `--bf-signal`).
2. **3D-модель** — сверху, `aspect-ratio: 4/3`, `max-height: 32vh`, на всю ширину. Вращение то же.
3. **Характеристики** — сетка 1 колонка (подпись слева, значение справа, `justify-content: space-between`).
4. **Кнопка действия** — `width: 100%`, `height: 48px`, сразу под характеристиками.
5. **Список мотоциклов** — **под** кнопкой, скроллируемый (`max-height: 38vh; overflow-y: auto;`), строки компактные как на desktop.
6. **«← НАЗАД»** — в самом низу панели, `width: 100%`.

Проверить на ширинах **320, 360, 390, 414, 430** px, что:
- Баланс не наезжает на логотип (при нехватке места — перенос баланса на вторую строку `flex-wrap: wrap`).
- Название мотоцикла в строке списка не наезжает на цену: `min-width: 0` у текстового блока, `text-overflow: ellipsis` на названии, цена `white-space: nowrap; flex-shrink: 0`.
- Кнопка не наезжает на свотчи, свотчи переносятся (`flex-wrap: wrap`).
- Характеристики не вылезают за рамку (`word-break: break-word; min-width: 0`).
- Нет горизонтального скролла.

## ⚙️ ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

1. **Не менять** логику покупки/выбора из текущего `renderShop` — только визуал и layout. Сохранить функции `saveGarage`, `ownedBikes`, `selectedBikeId`, `customColors`, `getBikeEffectiveStats`, `purchaseUpgrade` и т.д.
2. **Отдельная сцена для 3D-превью** не должна ломать основной рендер:
   - либо второй `WebGLRenderer` с `powerPreference: "low-power"`, `pixelRatio: 1`, `antialias: true`, размер canvas = размер области превью, `setAnimationLoop` только пока магазин открыт (`i.currentScreen === "shop"`), останавливать при уходе с экрана;
   - либо offscreen-рендер в `canvas` в правой колонке (как сейчас сделано для `camPreview` в настройках камеры — переиспользовать подход из `renderCameraPreview` / `X()`).
3. При открытии магазина — по умолчанию выбран для просмотра **текущий `selectedBikeId`**.
4. При клике по строке списка — только меняется «просматриваемый» мотоцикл (`shopPreviewId`), не `selectedBikeId`.
5. При покупке/выборе — обновить и список, и правую колонку, и `syncVehicleAndCameraVisibility`.
6. Учёт пробега по мотоциклам — новый ключ `localStorage` `bajajGO_mileage`, объект `{ [bikeId]: meters }`, обновлять при завершении заезда/уходе в меню/`pagehide`, по аналогии с `persistBiome`. При показе — форматировать через существующий `$o()`.
7. Стили — в общем `<style>`, использовать токены `--bf-*`. Не дублировать существующие классы `.ds-card`/`.ds-list` — завести новые (например, `.shop-row`, `.shop-preview`, `.shop-stats`).
8. Не ломать доступность: строки списка — `<button type="button">`, кнопка действия — `disabled` где нужно, фокус-обводка `outline: 1px solid var(--bf-accent)`.

## ✅ КРИТЕРИИ ПРИЁМКИ

**Desktop:**
- [ ] Магазин — двухколоночный: список слева, модель + характеристики + кнопка справа.
- [ ] 3D-модель выбранного мотоцикла вращается вокруг вертикальной оси, не зависит от FPS, останавливается при скрытой вкладке.
- [ ] Под моделью — характеристики (макс. скорость, разгон, тюнинг, тип) в стиле BF3.
- [ ] Для купленных мотоциклов показан пробег (в метрах/км) из `bajajGO_mileage`.
- [ ] Кнопка покупки/выбора — под характеристиками, состояния: ВЫБРАН / ВЫБРАТЬ / КУПИТЬ ЗА X ₽ / НУЖНО X ₽ (disabled) / не хватает X ₽.
- [ ] Клик по строке списка меняет модель и характеристики справа, не меняя `selectedBikeId`.
- [ ] Свотчи (если есть) — под кнопкой, перекрашивают модель в превью и в гараже.
- [ ] Баланс — в шапке панели, `--bf-signal`, не наезжает на логотип.

**Mobile (вертикально):**
- [ ] Одна колонка: шапка → модель → характеристики → кнопка → список → «назад».
- [ ] Модель `max-height: 32vh`, список `max-height: 38vh` со скроллом.
- [ ] Ничего не наезжает: баланс/логотип, название/цена в строках, характеристики, кнопка, свотчи.
- [ ] Нет горизонтального скролла, тач-таргеты ≥ 44×44.
- [ ] Стиль BF3 сохранён (тонкие рамки, 2px радиус, uppercase, `--bf-accent` / `--bf-signal`, прозрачность 0.62–0.82).

**Общее:**
- [ ] Логика покупки/выбора, экономика, Three.js-сцена заезда — не изменены.
- [ ] Пробег сохраняется между перезагрузками и корректно сбрасывается только при новом заезде (накапливается, а не перезаписывается).
